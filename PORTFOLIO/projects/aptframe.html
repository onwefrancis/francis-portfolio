Case study · AI tooling · 2025

Aptframe — the prompt-builder
workspace

I kept rewriting prompts and losing the good versions — so I built the fix. Aptframe converts a plain-English goal into a structured, reusable prompt through a guided seven-field brief, and keeps every version you save.

RoleSole designer & builder
StackNext.js · TypeScript · Supabase
Model layerGemini API · serverless
StatusLive & public
DEMO REEL · recorded live on aptframe-beta.netlify.app — brief in, structured prompt out

The problem

Good prompts are engineering artifacts — and I was treating them like sticky notes. Scattered across chats, subtly different each time, impossible to reuse or review. The craft of prompt design deserved the same discipline as any other specification: fields, constraints, versioning, reuse.

The build

  • Guided seven-field brief — goal, audience, context, constraints, format, examples, checks — that assembles a structured prompt no missing section can sabotage.
  • Model behind the wall: the Gemini API is called only from protected serverless functions; no keys in the browser, ever.
  • Supabase persistence for saved prompts and versions, so the good ones stop disappearing.
  • Deployed on Netlify with framework-aware builds; my first end-to-end production system.

Why it matters to my practice

Aptframe is where my prompt-design research lives, and where the honesty rules I now apply everywhere were first written down: an AI output is a draft to evaluate, not a fact to trust. That lesson went straight into how the AI assistant inside NCI RIMS behaves — guidance-only answers, sourced or silent.
